## 🎲 Durable Game Invariants

All engine logic and AI behavior must obey these core mathematical and domain rules:

*   **Coordinate System**: Cube Coordinates (`q, r, s`) are mandatory for all board geometry and logic. Do not use offset coordinates for state or logic.
*   **Distance Rule**: Strictly enforce that no settlement or city may be adjacent to another vertex occupied by a settlement/city. This is an area-denial mechanism.
*   **Probability & Pips**: Dice rolls follow the standard 2d6 Bell Curve (36 permutations). Pips (1 to 5) measure raw production potential.
*   **Layer Boundaries**: Logic in MOVES (`src/game/moves/`) must never import from BOTS (`src/bots/`). UI components (`src/features/`) consume game state but logic must not bleed into component render trees.

## 🛡️ Verification & Operational Constraints

*   **Mandatory TDD & Verification**: Write tests alongside or before implementing game logic. Verify changes by running tests (`npm test`) and build checks (`npm run build`) before marking tasks complete.
*   **UI / Visual Verification**: When modifying UI/UX components, run Playwright E2E tests (`npm run test:e2e`) or generate screenshots to confirm visually.
*   **Generated Evidence**: `.maritime/*` and `docs/images/dependency-graph.svg` are generated by the single Generated Artifacts writer. Do not hand-edit them; use the pinned workflow in `docs/DEVELOPMENT.md`.
*   **No Fixed Timeouts**: Never use `waitForTimeout` in Playwright tests; always wait for explicit DOM selectors or state conditions.
*   **Strict Typing**: Always use strict TypeScript with specific interfaces. Do not use `any`.
*   **Active Tasks**: All Phase 7 and remaining roadmap work must be checked against and tracked in `docs/ROADMAP.md`.
